## 概要

毎日の筋トレメニューと食事の目安を自動で出し、やった分だけ培養カプセルの中の「分身」が育つ育成ゲーム。2026-11-19 に初版（v1.0.0）を作り、ルール部分の自動チェック（PASS 207,856項目）と、Claude の内蔵ブラウザ（iPhone サイズ）での通し操作で動作を確認した。PWA化と Claude Artifact での公開まで済み。スマホ実機での確認、GitHub Pages での公開、iOS化は未着手。以後の変更は #0002 以降に記録する。

## 対象ファイル

パスは `マッスルラボ/` からの相対パス。

- `index.html` — アプリ本体。HTML・CSS・JavaScript をこの1ファイルに収める（約180KB・約2,400行）
- `manifest.json` / `sw.js` — PWA の設定と Service Worker
- `icon.svg` / `icon-192.png` / `icon-512.png` / `apple-touch-icon.png` — アイコン

- `tools/make-artifact.sh` — Claude Artifact に載せる版を作る
- `tools/make-icons.sh` — `icon.svg` から PNG を作り直す
- `README.md` — アプリの状態・URL・残作業
- `.claude/launch.json` — ローカル確認用サーバ（`python3 -m http.server 8821`）の設定
- `.claude/rules/documentation.md` / `docs/` — ドキュメント規則と開発ドキュメント

## 企画

依頼は「毎日の筋トレメニューを自動で提案し、目安となる食事も提案し、日々のモチベーションになるゲーム」。名前は「マッスルラボ」。育成型・ボス討伐型・ラボ経営型の3案から、清武が育成型を選んだ。

- 「ラボ」の名前に合わせ、筋トレを「実験」、休む日を「回復日」、週のまとめを「研究発表」と呼ぶ
- 核になる考え: **正しい鍛え方とゲームのルールを一致させる。** 同じ部位を毎日鍛えさせず、休む日も記録すれば連続日数が続く。分身が弱ったり縮んだりする罰は入れていない

## 仕様

### はじめての設定（5ステップ）

1. 目的: 筋肉をつける（`bulk`）/ 体をしぼる（`cut`）/ 健康を保つ（`keep`）
2. 器具: 自重のみ（`body`）/ ダンベルあり（`dumbbell`）/ ジムに通う（`gym`）。上の設定は下の種目も含む
3. ペース: 1回の時間（10・20・30分）と、週に実験する日数（2〜6日）
4. 体のデータ: 性別（男性・女性・答えない）、年齢（13〜90）、身長（120〜220cm）、体重（30〜200kg）。食事の目安の計算だけに使う
5. 分身の名前（12文字まで）

最初の画面では、分身が育ってポーズをとる様子をくり返し見せる。設定はあとから「設定」で変えられる。

### 部位・レベル・回復

- 部位は 胸・背中・脚・腹・肩・腕 の6つ
- 次のレベルまでに要る経験値は `60 + 25 × (レベル − 1)`（Lv.1→2 は60、Lv.2→3 は85 …）。上限は Lv.99
- 見た目の育ち具合は `((レベル − 1 + 端数) ÷ 29) ^ 0.75`。Lv.30 で最大になり、序盤ほど変化が大きい
- 1セットの経験値は `10 × (0.8 + 0.2 × 種目の難しさ1〜5)`。主に効く部位に全部、補助で効く部位に40%が入る
- 鍛えた部位（主に効く部位）は、その日を0日目として 2日（腹は1日）たつまで「回復中」。回復中の部位はメニューに入らない

### その日が実験の日か回復日か

その日を開いたときに、過去の記録から決める（`decideType`）。次のどれかに当てはまると回復日。

- 回復が済んだ部位が1つもない
- 直前の6日間に、設定した日数ぶん実験している
- 連続で実験した日数が上限に達した（週3日以下: 1日、週4日: 2日、週5日: 3日、週6日: 6日）
- 前回の実験からの日数が `7 ÷ 週の日数`（切り捨て）に足りない（週2日なら中2日あける）

この決め方で、続く7日間のどこを取っても設定した日数を超えない。サボった日は数えないので、次に開いた日が実験の日になる。使う人は「今日は休む」「それでも実験する」で切り替えられる（その日の記録を付ける前だけ）。

### メニューの自動提案

- 1回の時間で形が決まる: 10分 → 3種目・2部位・各2セット、20分 → 5種目・3部位・各3セット、30分 → 7種目・4部位・各3セット
- 部位は、回復が済んだものを「長く鍛えていない順 → レベルが低い順 → 胸・背中・脚・腹・肩・腕の順」に並べ、上から選ぶ
- 種目は、器具の設定と部位のレベルで使えるものの中から、点数の高い順に選ぶ。点数 = 解放レベル ＋ 器具の一致（設定と同じ器具 +3.2、1つ下 +1.2）− 直近3日以内にやった種目 1.4 ＋ 日付で決まる乱数 0〜2.4。同じ日は何度開いても同じメニューになる
- 腹の種目は最後に並べる
- 回数は「種目の基本の回数 ＋ これまでの増減」。しぼる目的では +2回（秒の種目は +5秒）。上限は、重りを使う種目が15回、自重が20回（基本の回数の2倍のほうが大きければそちら）、秒の種目が120秒
- 休憩は、しぼる目的が30秒、筋肉をつける目的で重りを使う種目が60秒、それ以外は45秒
- メニュー画面で、種目ごとの入れ替えと、メニュー全体の作り直しができる。種目の説明から「メニューに出さない」を選ぶと、以後その種目は出ない

### 実験の進め方と集計

- 流れ: メニュー確認 → 種目ごとに「セット完了」→ 休憩タイマー（+15秒・スキップ可）→ 最後に負荷の感想 → 結果
- 回数は ＋／− で実際にやった数に直せる。秒の種目は 3秒の準備のあとタイマーが動き、終わると自動でセット完了になる（左右ある種目は反対側も続けて計る）
- 重りを使う種目は、使った重さをメモできる（ダンベル 1kg 刻み、ジム 2.5kg 刻み）
- 途中で閉じても進み具合は残る。「ここまでで終える」で、できた分だけ集計する。感想を答えないまま日付が変わったときは、次に開いたときに「ちょうどいい」として自動で集計する
- 次回の回数の増減: 楽だった +2、ちょうどいい +1、きつかった −2。実際の回数が目標より少なければさらに −1、多ければ +1。重りを使う種目で上限の回数に達していたら、回数を基本に戻して、次回から重さを一段上げる
- 研究ポイント: セットの半分以上をやった実験 +50（それ未満は +20）、レベルアップ1つにつき +10

### 食事の目安

- 基礎代謝は Mifflin-St Jeor の式（男性 `10×体重 + 6.25×身長 − 5×年齢 + 5`、女性は末尾が −161、答えないは −78）
- 1日に使う量 = 基礎代謝 × `1.3 + 0.03 × 週の日数`（30分の設定はさらに +0.05）
- 目的ごとの調整: 筋肉をつける ×1.1、体をしぼる ×0.85（減らすのは最大500kcal）、健康を保つ はそのまま。基礎代謝と、男性1,500kcal・それ以外1,200kcal を下回らない。18歳未満は減らさない。50kcal 単位に丸める
- たんぱく質は体重1kgあたり 1.8g（つける）/ 2.0g（しぼる）/ 1.4g（保つ）、上限200g。脂質はカロリーの25%、残りが炭水化物
- 1日の量を 朝25%・昼35%・夜30%・間食10% に分ける（たんぱく質は 25・30・30・15%）
- 例は全69件（自炊25・コンビニ24・外食20）。食事ごとの目安にいちばん合う例を選ぶ。ごはんの量（100〜250g）を目安に合わせて決め、たんぱく質が足りなければプロテインかゆで卵を、カロリーが足りなければ牛乳やバナナを足す
- 「食べた」を押すと栄養チャージが 25% たまる。その日の実験の経験値に、チャージ × 50% のボーナスがつく（実験の前でも後でも同じ結果になる。取り消すとボーナスも戻る）。1回につき +5 RP
- 数値は一般的な計算式と食品成分にもとづく目安で、診断や治療の代わりにはならないことを画面に書いてある

### 続ける仕掛け

- 連続日数: 実験した日も、回復を記録した日も数える。3・7・14・30・50・100・200・365日でボーナスの RP
- 研究ランク（RP の合計）: 見習い研究員 0 → 研究員 200 → 主任研究員 600 → 室長 1,500 → 准教授 3,000 → 教授 6,000 → 所長 10,000 → 名誉所長 16,000。ランクごとに培養液の色（8色）、カプセルの土台の素材、ランプと泡の数が変わる
- 研究発表: 毎週月曜に前の週（月〜日）を採点する。実験の回数 50点 ＋ 記録した日 20点 ＋ 食事の記録 20点 ＋ 鍛えた部位の数 10点。85点以上 S（+200 RP）、70点以上 A（+120）、45点以上 B（+60）、それ未満 C（+20）
- 部位のレベルが上がると、新しい種目が解放される（種目図鑑で確認できる）
- カプセルを押すと分身がポーズをとる。回復中の部位はオレンジ色に光る
- 研究メモ: 日替わりのひとこと（18件）

### 画面

- 下にタブ3つ: ラボ（ホーム）/ 食事 / 記録
- ラボ: 研究ランクと連続日数、培養カプセル（分身と6部位のチップ）、今日のカード、栄養チャージ、今週の記録、研究メモ
- 食事: 1日の目安、栄養チャージ、場面の切り替え、朝・昼・夜・間食のカード、計算のしかた
- 記録: 実験回数などの数字、部位のバランス（レーダーチャート）、カレンダー、体重の記録と推移、研究発表の履歴、種目図鑑
- 設定: 名前・目的・器具・ペース・体のデータ、効果音と振動、記録の書き出し・読み込み（文字のコピーと貼り付け）、記録の消去（2段階の確認）
- 分身・カプセル・アイコン・グラフはすべて SVG をその場で組み立てる（画像ファイルなし）。分身は部位ごとの育ち具合から形を計算する
- 効果音は WebAudio でその場で作る（音源ファイルなし）。`navigator.vibrate` で触覚。実験中は画面が消えないようにする（対応している環境だけ）
- 配色は暗い1種類のみ（夜の研究室）。フォントは端末のものだけを使う

### 保存

- `localStorage` のキー `musclelab.v1` に1つの JSON で保存する。通信はしない
- 中身: `profile`（設定）、`parts`（部位ごとの経験値と最後に鍛えた日）、`ex`（種目ごとの回数・増減・重さ・出さない印）、`rp`、`liquid`（培養液の色）、`streak`、`days`（日ごとの記録）、`cur`（今日のメニューと進み具合）、`weights`（体重）、`weeks`（研究発表）、`totals`、`set`（音・振動・食事の場面）
- 読み込むときに形を確かめ、欠けた値や範囲外の値は既定値に直す

### PWA

- `manifest.json`: 名前「マッスルラボ」、縦向き固定、背景と帯の色 `#080D18`、アイコン3種（SVG・192px・512px）
- `sw.js`（キャッシュ名 `musclelab-v3`）: 本体・manifest・アイコンを先に保存する。同じフォルダのファイルは、保存してある版をすぐ返し、裏で新しい版を取りに行く（次に開いたときに新しい版になる）。`?debug=1` のような付け足しは無視して同じファイルとして扱う。つながらないときは、ページを開く要求にだけ本体を返す
- Service Worker を登録するのは、http(s) で直接開いたときだけ。ファイルを直接開いたとき、iframe の中（Claude Artifact）では登録しない
- `index.html` の `<head>` にある PWA 用のタグ（manifest・アイコン）と、末尾の Service Worker の登録は、印（`@artifact-start` 〜 `@artifact-end`）の外に置いてある。Artifact に載せる版（`tools/make-artifact.sh`）には入らない
- PNG のアイコンは角を丸めない四角で作る（`tools/make-icons.sh`）。ホーム画面では iOS や Android が自分で角を丸めるため

### 動作確認用の入口

- URL に `?debug=1` を付けると `window.__mlab` が使える。`S`（保存データ）、`shiftDays(n)`（日付を進める。値は sessionStorage）、`simulate(感想)`（今日の実験を全部やったことにする）、`reset()` など
- `tools/check.mjs` は、`index.html` のスクリプトを Node.js の中で動かし、同じ入口からルールを確かめる

## 確認

- `node tools/check.mjs`: PASS 207,856項目。目的3 × 器具3 × 時間3 × 日数5 = 135通りの設定で77日ぶん（実験5,940回）を再現し、回復中の部位がメニューに入らないこと、未解放や器具外の種目が出ないこと、続く7日間で設定の日数を超えないこと、全部位を鍛えること、連続日数・研究発表・保存と読み直しを確かめた。気まぐれな使い方（休む・サボる・途中で閉じる）200日ぶんと、食事の目安（性別3 × 目的3 × 体重5 × 年齢3）も確かめた
- Claude の内蔵ブラウザ（375×812、音は消して操作）: はじめての設定、ホーム、実験（開始・休憩タイマー・+15秒・中断と再開・秒の種目のタイマー・途中で終える）、結果、食事（記録・別の例・場面の切り替え・計算のしかた）、記録（レーダー・カレンダー・体重のグラフ・研究発表・種目図鑑）、設定（各項目・書き出し・読み込み・消去）、翌日の回復日、研究発表、ランクアップ。パソコンの幅（1024px）でも表示が崩れないこと
- オフライン: サーバを止めた状態で読み込み直し、Service Worker のキャッシュから開けることを確かめた
- Claude Artifact: 公開した。Artifact と同じ制限（外部の読み込みを止める設定と、自動で付く枠）を手元で再現した環境で、設定から実験・食事・記録まで動き、遮断やエラーが出ないことを確かめた
- **未確認**: スマホ実機での表示と操作、実物の Artifact のページ（内蔵ブラウザではサインインが要るため開けなかった）、効果音の聞こえ方、振動
