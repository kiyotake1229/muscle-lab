## 概要

Web 版のマッスルラボ（`index.html`）を、Capacitor 7 で iOS アプリにするプロジェクト（`ios-app/`）を作った。アプリの中だけ動く機能として、実験の時間のお知らせ（ローカル通知）、触覚フィードバック、記録の控え（端末の保存領域への二重保存）を本体に足した。Web・PWA・Claude Artifact での動きと、ゲームのルールは変えていない。App Store のアップロードで確かめられる申告（プライバシーマニフェスト・暗号化・言語）も入れた。Xcode でのビルドは、GitHub Actions のビルド確認で通ることを確かめた（2026-11-20、Xcode 26.6。この Mac には Xcode が無い）。**シミュレータ・実機での起動と動作は未確認**。

## 変更内容

### 1. iOS プロジェクト（`ios-app/`）

**使っている部品**（`ios-app/package-lock.json` で固定）

| 部品 | 版 | 使いみち |
|---|---|---|
| `@capacitor/core` / `@capacitor/ios` / `@capacitor/cli` | 7.6.10 | 本体 |
| `@capacitor/haptics` | 7.0.5 | 触覚 |
| `@capacitor/local-notifications` | 7.0.7 | 実験の時間のお知らせ |
| `@capacitor/preferences` | 7.0.4 | 記録の控え（UserDefaults） |
| `@capacitor/assets` | 3.0.5 | アイコン・起動画面の生成（開発時だけ） |

**設定**（`capacitor.config.json`）

- `appId`: `work.ltv.musclelab`、`appName`: `マッスルラボ`、`webDir`: `www`
- `ios.contentInset`: `never` — 本体が `viewport-fit=cover` と `env(safe-area-inset-*)` でノッチやホームバーを避けているため、iOS 側では余白を足さない
- `ios.backgroundColor`: `#080D18` — 本体の地の色。起動直後に白く光らないようにする
- `ios.preferredContentMode`: `mobile` — iPad でもスマホ向けの表示にする（そなえ帳・思考力と同じ）

**作り方**（作り直すときの手順）

`node_modules/`（約100MB）を Dropbox に置かないよう、Dropbox の外に `マッスルラボ/` の写しを作って、その中で実行した。できた `ios-app/` を、`node_modules/` と `xcuserdata/` を除いて Dropbox に戻している。

```bash
cd ios-app
npm install
npm run sync-web                 # ../index.html などを www/ にコピー
npx cap add ios                  # ios/ を作る
npm run icons                    # assets/ からアイコンと起動画面を作る
npx cap sync ios                 # public/ へのコピーと pod install
```

- `npx cap add ios` と `npx cap sync ios` は、最後に `xcodebuild clean` を実行する。Xcode が無い Mac ではここだけ失敗する（表示は「Updating iOS native dependencies with pod install - failed!」）。その前の、Web 資産のコピー・プラグイン3つの登録・`pod install`（Capacitor・CapacitorCordova・Haptics・LocalNotifications・Preferences の5つ）は済んでいる。`ios/App` で `pod install` を単独で実行すると「Pod installation complete!」になることで確かめた
- `npm run icons` のあと、`ios/App/App/Assets.xcassets/Splash.imageset/` に雛形の `splash-2732x2732*.png`（3枚。どこからも使われない）が残るので消した
- `assets/icon.png` と `assets/splash.png` の両方があると、`@capacitor/assets` は起動画面を2回作る（先に `icon.png` から、あとで `splash.png` から）。残るのは `splash.png` から作ったほう。できた画像が `assets/splash.png` と同じ絵であることを確かめてある

**`ios/App/App/Info.plist` に入れたもの**（`npx cap add ios` のままから変えた点）

| キー | 値 | 理由 |
|---|---|---|
| `CFBundleDevelopmentRegion` | `ja`（もとは `en`） | 通知の許可のダイアログなど、iOS が出す文言を日本語にする |
| `CFBundleLocalizations` | `ja` だけ | 同上 |
| `ITSAppUsesNonExemptEncryption` | `false` | 通信をしないので暗号化を使っていない。アップロードのたびの質問が出なくなる |
| `UISupportedInterfaceOrientations` | 縦向きだけ | iPhone は縦向き固定（`manifest.json` と同じ）。iPad は4方向のまま |
| `UIStatusBarStyle` | `UIStatusBarStyleLightContent` | 画面が暗い1色なので、ステータスバーの文字を白にする。Capacitor の画面（`CAPBridgeViewController`）がこのキーを読んで文字の色を決める |
| `UIUserInterfaceStyle` | `Dark` | 端末がライトモードでも、キーボードやメニューを暗い色で出す |

- ローカル通知のために `Info.plist` に足すキーは無い（通知には、カメラや写真のような「使う理由の説明文」のキーが無い）。Push Notifications の Capability も要らない。通知を受け取る役（`UNUserNotificationCenter` の delegate）は Capacitor が自分で設定するので、`AppDelegate.swift` も雛形のまま
- バージョンは、本体の表示（設定の「マッスルラボ v1.0.0」）に合わせて `MARKETING_VERSION = 1.0.0`、ビルドは 1

**プライバシーマニフェスト**（`ios/App/App/PrivacyInfo.xcprivacy`）

- トラッキングなし（`NSPrivacyTracking = false`）、トラッキング用のドメインなし、収集データなし（App Store Connect の「データを収集しません」と同じ）
- 理由の申告が要る API は UserDefaults（`NSPrivacyAccessedAPICategoryUserDefaults`、`CA92.1`: アプリ自身のデータの読み書き）だけ
- **申告の決め方**: 入れた部品の iOS 側のソース（`node_modules/@capacitor/*/ios/` と `@capacitor/ios/Capacitor`・`CapacitorCordova`）を、UserDefaults・ファイルの日時・空き容量・起動してからの時間・キーボードの一覧の API 名で検索した。当たったのは `@capacitor/preferences` の `UserDefaults.standard` だけ（記録の控えに使う）。Haptics・LocalNotifications・Capacitor 本体には無い。Capacitor 本体と CapacitorCordova は自分用のマニフェストを持っていて、中身は空。`@capacitor/preferences` は自分用のマニフェストを持っていないので、アプリ側の申告が要る
- **Xcode のプロジェクトへの登録**: 手元に Xcode が無いため、CocoaPods に入っている xcodeproj（Ruby）で、App ターゲットの Resources に追加した。CocoaPods が Homebrew で入っている場合の実行例:

```bash
cd ios-app/ios/App
GEM_HOME="$(brew --prefix cocoapods)/libexec" "$(brew --prefix ruby)/bin/ruby" -e '
require "xcodeproj"
project = Xcodeproj::Project.open("App.xcodeproj")
target = project.targets.find { |t| t.name == "App" }
group = project.main_group["App"]
ref = group.files.find { |f| f.path == "PrivacyInfo.xcprivacy" } || group.new_file("PrivacyInfo.xcprivacy")
ref.last_known_file_type = "text.xml"
phase = target.resources_build_phase
phase.add_file_reference(ref) unless phase.files_references.include?(ref)
target.build_configurations.each { |c| c.build_settings["MARKETING_VERSION"] = "1.0.0" }
project.save'
```

保存のときに、中身が空の `packageReferences` の項目が外れる（Swift Package は使っていないので影響なし）。変わったのは、この登録とバージョンの行だけであることを差分で確かめた。

**アイコンと起動画面**

- `tools/make-icons.sh` が `icon.svg` から `ios-app/assets/` の3枚を作る。アイコンは角を丸めない四角（iOS が自分で丸めるため）。`npm run icons` で 1024px・透過なしの PNG になる
- 起動画面は、本体の地の色（`#080D18`）1色の中央に、フラスコの絵だけを置いた。光のぼかしを入れると PNG が1枚 1MB を超え、アプリに6枚入るので、地は1色にした（1枚 約0.19MB）
- **sips の癖**: macOS の `sips` は、大きさと viewBox が違う SVG（512 の絵を 1024 で描かせる）だと、グラデーションの位置がずれる。viewBox ごと 1024 にして、中身を `scale(2)` で広げて描かせている。できた 1024px を 512px に縮めて、既存の `icon-512.png` と同じ絵になることを確かめた

### 2. 本体の変更（`index.html`）

どれも `NATIVE`（`window.Capacitor.isNativePlatform()` が true）のときだけ動く。Web・PWA・Claude Artifact では `window.Capacitor` が無いので、今までどおり動く。外部との通信は増やしていない。プラグインは、Capacitor が WebView に用意する `window.Capacitor.Plugins` から直接呼ぶ（本体は1ファイルのままで、部品の JavaScript は同梱しない）。呼び出しは `capCall(プラグイン, メソッド, 引数)` にまとめ、部品が無い・失敗したときは `null` を返して例外を外に出さない。

**記録の控え（二重保存）**

- `store.set`（保存）のたびに、同じ JSON を `Preferences.set`（キー `musclelab.v1`。実体は UserDefaults）にも書く。`store.del`（記録の消去）では `Preferences.remove` も呼ぶ。消したはずの記録が、次の起動で控えから戻ってこないようにするため
- 起動時、localStorage に読める記録が無いとき（空、または壊れていて読めないとき）だけ、`Preferences.get` の内容から戻す（`restoreNative`）。戻したら localStorage に書き戻し、「記録を復元しました」と出す。localStorage に記録があるときは控えを読まない
- 控えの返事が2秒来なければ、待たずに始める（画面が出ないまま止まらないようにする）
- 起動の流れ（`boot`）は、控えを読むあいだだけ待つ形にした。Web では待たずに、今までと同じ順で始まる

**触覚**（`buzz`）

- アプリの中では `Haptics.impact` を使う。`navigator.vibrate` 用の「ミリ秒」の指定を、強さに読み替える: 20未満は LIGHT、20以上は MEDIUM、50以上は HEAVY
- 配列（振動・休み・振動…）は、振動のところごとに1回ずつ、もとの間隔で出す（例: `[30,50,30,50,80]` は MEDIUM → 80ミリ秒後に MEDIUM → さらに80ミリ秒後に HEAVY）
- アプリの外では、今までどおり `navigator.vibrate`。設定の「振動」が OFF なら、どちらも呼ばない

**実験の時間のお知らせ**（ローカル通知）

- 設定は `S.set.remind`（ON/OFF。初期値 `false`）と `S.set.remindAt`（時刻。初期値 `19:00`）。壊れた値は読み込むときに初期値へ直す
- 設定シートの「音と振動」の下に「お知らせ」の欄を足した。**アプリの中だけ出る**（Web・PWA には通知を届けるしくみが無いので、欄ごと出さない）。ON/OFF のスイッチと、ON のときだけ出る時刻（−／＋。1回押すと5分、押しつづけると30分きざみにそろえて進む。0時をまたいで回る）
- **許可は ON にしたときにだけたずねる**（`remindAllow`）。断られたら ON にせず、端末の設定で許可するよう案内を出す。起動時やアプリに戻ったときは、許可がまだ有効かを確かめるだけで、たずねない。端末の設定で通知を切られていたら、アプリの中の設定も OFF に戻して知らせる
- 予約のしかた（`remindList` / `syncRemind`）: 今日から14日ぶんを、設定した時刻に1日1件ずつ予約する（通知の番号は 4100〜4113）。予約し直すときは、先に14件を取り消す
  - 過ぎた時刻と、1分以内の時刻は予約しない（プラグインは、過ぎた時刻を渡すとその場で通知を出してしまうため）
  - 今日のぶんは、**その日の実験を始めたあと（1セットでも記録したあと）と、記録を済ませたあとは入れない**
  - 今日のぶんの文面は、その日の予定に合わせる。実験の日は「実験の時間です」／「今日は 胸・背中・脚 の5種目（約22分）。（分身の名前）が待っています。」、回復日は「今日は回復日です」／「回復を記録すると、連続日数が続きます。」
  - 明日以降のぶんは、その日の予定がまだ決まっていない（開いた日に決まる）ので、「実験の時間です」／「ラボを開いて、今日のメニューを確かめましょう。」
  - 14日のあいだ一度も開かれなければ、お知らせは止まる
- 予約し直すのは、記録を保存するたび（0.9秒まとめて）・起動したとき・アプリに戻ったとき・記録を読み込んだとき・記録を消したとき。予約の中身が前と同じなら、プラグインを呼ばない
- 時刻は JavaScript の `Date` のまま渡す（このプラグインは `schedule.at` を日付の型でしか受け取らない。文字にして渡すと時刻なしの扱いになり、その場で通知が出る）。iOS 側では「今から何秒後」の予約になるので、端末の時刻を進めても早くは届かない
- 通知音は `sound: ''` を付けている。このプラグインは、iOS では `sound` の指定が無いと無音になり、空（見つからない名前）なら端末の標準の通知音が鳴る
- 分身の名前に `%` が入っていたら、通知の文面では全角の `％` に置き換える（iOS が通知の文面を書式の文字列として読むため）

**そのほか**

- Service Worker は、アプリの中では登録しない（もともと `capacitor://` では登録しない条件だったが、条件に明記した）。`sw.js` は `www/` にコピーしない
- 確認用の入口（`__mlab`）に `NATIVE`・`buzz`・`restoreNative`・`remindList`・`syncRemind`・`remindAllow` を足した
- 本体のバージョン表示は `1.0.0` のまま（Web での動きは同じ。App Store に出す最初の版も 1.0.0）

### 3. 自動チェック（`tools/check.mjs`）

「5. iOS アプリの中の動き」を足した（50項目。2026-11-19 の実行で合計 PASS 207,906 項目）。にせものの `window.Capacitor` がある環境でアプリの本体をもう一度動かし、プラグインの呼び出しを記録して確かめる。時刻は 2026-11-19 10:00 に固定している。

- Web では `NATIVE` が false で、何も呼ばないこと
- 保存のたびに控えにも同じ内容を書くこと。localStorage が空のときだけ控えから戻すこと（記録があるとき・控えが壊れているとき・控えが無いとき・部品が無いときは戻さない）。控えの返事が来ないときに約2秒で進むこと。記録を消すと控えも消えること
- 触覚の強さの読み替えと、配列の回数。振動を OFF にすると呼ばないこと
- お知らせ: 起動しただけでは許可をたずねないこと。予約の件数・番号・日時・文面・通知音の指定。同じ内容なら呼び直さないこと。実験を始めたあと・記録を済ませたあと・回復を記録したあとは今日のぶんが無いこと。過ぎた時刻を予約しないこと。OFF で取り消すだけになること。許可されていないときに設定が OFF に戻ること。予約に失敗したあとでやり直すこと
